# Security Policy

Do not disclose vulnerabilities, pairing codes, device credentials, private
keys, configuration files, or local session data in public issues.

Report a suspected vulnerability through the repository's GitHub private
security advisory feature. Include reproduction steps, affected version, and
impact. Do not create a public issue for a security report.

Before a 1.0 release, official Windows and macOS artifacts must be code-signed.
Every release also publishes SHA-256 checksums. Verify the checksum before
running an archive downloaded outside the official release page.
